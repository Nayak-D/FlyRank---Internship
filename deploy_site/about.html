About the work

Evidence-led search and content refresh recommendations

This portfolio shows a practical approach to search data problems: use real signals, keep the workflow reviewable, and build a live case study without adding features that are not already supported by the evidence.

Approach

I focus on useful evidence, clear constraints, and human decisions. The model is built to surface opportunities, not to replace editorial judgment. Every recommendation is meant to be verified before a refresh action is taken.

  • Frame the problem as a review queue, not an automatic ranking system.
  • Use simple validation so the result is trustworthy.
  • Keep the portfolio readable and grounded in actual work files.

Skills shown

  • Problem framing for refresh and ranking tasks
  • Data boundary definition and client-holdout validation
  • Model comparison with a clear baseline
  • Evidence presentation with charts and queue preview

Build stack

This site is built with plain HTML and CSS in the repository root, with a shared stylesheet for consistency. That keeps the portfolio easy to explain and maintain without a build pipeline or framework dependencies.

Still ugly

This version is intentionally rough and live. The parts I already know are still rough include:

  • The page layout is basic and the spacing could be more polished.
  • There is no headshot or personalized branding beyond the monogram.
  • The charts are embedded in the raw exported form instead of a refined presentation layer.
  • Contact details are a working placeholder for a future preferred address.
  • Mobile layout is passable, but the smallest screens may still feel tight.

Every site page is built from the same repository evidence and linked in the navigation above.
