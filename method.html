Method and evidence

How the refresh ranking was built and validated

This page describes the research question, the data boundary, the ranking task, the validation strategy, and how the result is meant to support human review instead of replacing it.

Research question

Which existing pages should a content team review first for a refresh, based on declining search performance and continuing demand?

The work is framed as a ranking task: the output is a queue of pages ordered by the likelihood that they deserve a refresh action.

Data contract and validation

The model uses 30,000 anonymized page snapshots from the provided dataset. It excludes titles, URLs, and client identifiers from the prediction target so it does not learn site-specific labels directly.

Validation uses a client-holdout split, which keeps entire clients out of training so the model’s score is tested on truly unseen pages. That helps reduce the risk of overfitting to one client’s traffic patterns.

Signal audit

The strongest features include:

  • days_with_impressions: shows ongoing visibility.
  • log_impressions_90d: captures exposure over the last 3 months.
  • avg_position: identifies pages slipping in search rank.
  • content_age_days: avoids chasing pages that were just published.

Baseline vs model

The baseline rule is a simple score that captures decline and traffic signals. The selected random forest model outperforms that baseline on the chosen ranking metric.

  • Baseline precision at top 50: 0.240
  • Selected random forest precision at top 50: 0.740

That means the model should place more actual declining pages higher in the queue than the baseline rule.

Action workflow

  • Frame the recommendation as a review queue, not an automated publish list.
  • Score pages with the model and label them by confidence.
  • Validate using client-holdout and manual spot checks.
  • Act by sending high-confidence candidates to editorial review.
